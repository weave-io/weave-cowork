How the agent does it

Making an artifact, and how it knows to

One tool, the same for every agent

CoWork's MCP server (the one that already gives agents cowork_read_channel and cowork_resolve_thread) gets one more tool. The harness lists its tools and reads their descriptions, so the agent knows it can show things without anyone telling it. A template's instructions can add when ("produce reports as HTML and show them").

cowork_show({
  path:  "reports/tax-apis/index.html",  // a file in its workspace; the folder's images, CSS and scripts go with it
  title: "Tax APIs compared",
  open:  "canvas"                         // "canvas": opens beside the thread for whoever is looking; "card": just the card
})
// → { artifact: "a_7f3", version: 2, url: "https://cowork.lumen.example/a/a_7f3" }

What happens

1 · It writes a fileAn HTML report in its workspace, like any file it makes: in its sandbox or its worktree.
2 · It calls cowork_showThe runner reads the file and its folder (up to 25 MB) and uploads them with the thread's token.
3 · CoWork keeps itArtifactPublished: version 1 of an artifact tied to the thread and the project's library. Same path again is version 2.
4 · People see itA card in the thread; the canvas opens for whoever is looking at the thread. Search finds it by title and text.
5 · They ask for changes"Ask researcher to change…" under the canvas is a reply in the thread, quoting the artifact and version.

Kept safe

An artifact is the agent's code running in people's browsers, so it never runs inside CoWork's page:

  • Served from its own address (/a/… on a separate host name, or a sandboxed iframe with no same-origin), so it can't read CoWork's cookies or call its API as you.
  • A strict content policy: it loads only its own files. No network calls out, so a report can't phone home with what's on screen.
  • Seen by the people who can see the thread's channel; deleted with the channel; every version and who published it is in the audit.
  • Kinds: HTML, markdown, images and SVG, CSV and JSON shown as tables, PDF. Anything else is a download.

The three options, side by side

A · Canvas beside the thread Recommended start

Like Weave Fleet's canvas. Cards in the conversation; artifacts open in tabs on the right, with versions and "ask for a change". The thread stays readable beside it.

B · Inline, then pop out

Small things (a chart, a table) show right in the message; anything bigger pops out to the canvas. Good for quick looks, heavy for long reports.

C · A project library

Every artifact a project's agents and people made, in one place, findable later. Not instead of A: where A's artifacts live after the thread is done.
